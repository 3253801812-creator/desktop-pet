## 这一轮修掉的问题（三路只读审核 → 落地 22 类）

按"是否真的影响使用"排序，完整表格见 `README.md` 第十节。最要紧的四条：

1. **菜单被窗口裁掉**：加了闹钟一项后菜单高 632px、窗口只有 542px，菜单顶部被顶到窗外 98px —— 「形象」那排按钮整个看不见。
2. **三类"透明窗永久吃掉点击"**（也就是"抢鼠标"）：拖拽丢一次结束事件、渲染进程崩溃、隐藏状态下的显示路径，都会让窗口永久接收鼠标。现在分别有 10 秒看门狗、自动重载、真实可见性判断。
3. **闹钟**：任务到点会顺手清掉用户刚设的闹钟；退出就丢。现在都不会了，并且过期闹钟不会一开机补弹。
4. **数据安全**：写盘改原子替换；设置补丁只收已知键；设置窗口未保存的草稿不会被广播冲掉。

## 维护记录：一次"启动不了"的排查（2026-09-16）

现象：双击桌宠 exe，看不到桌宠。

查证过程与结论：

| 观察 | 结论 |
|---|---|
| 进程存在（1 个主进程 + 4 个辅助进程）、stderr 全空 | 程序**启动成功**，不是崩溃 |
| 枚举窗口：`记事本桌宠` 窗口存在，但 `IsWindowVisible = False` | 窗口建好了却**没显示** |
| 读 `settings.json`：`petVisible = false` | **根因**：之前点过菜单里的「隐藏桌宠」，这个开关被写进配置了 |
| 把 `petVisible` 改回 `true` 并重启 | 窗口 `IsWindowVisible = True`，`layered/transparent` 标志正确 |
| 另做实验：用 CDP 把整个 body 涂成纯红 | 屏幕对应区域出现红色 → **透明窗口的合成是正常的**，不是显卡/合成问题 |
| 立绘素材体检：`mumu-1.gif` 500×500、85% 不透明、平均 RGB(168,151,127) | 素材本身没问题，DOM 里 `naturalWidth=500`、`opacity=1` |

结论与恢复办法：**右键菜单里的「隐藏桌宠」会写进 `settings.json`（持久化），下次启动也不会显示**。恢复有两种：

- 托盘图标右键 → 「显示桌宠」（勾上）；
- 或直接改 `%APPDATA%\notepad-pet-app\settings.json` 里的 `petVisible` 为 `true`。

> 待改进（还没做）：`petVisible=false` 时如果用户又去双击 exe，除了开设置窗口之外，应该给个明确提示，而不是"什么都不发生"。已记在 `README.md` 第十节。

## 0.5.13：默认不自启 + 日程默认空 + 空日程友好提示

需求：不要开机自动启动、日程默认空、空的时候给一句友好提示、自启改成自己选。

| 项目 | 改动前 | 改动后 |
|---|---|---|
| `autoStart` 默认值 | `true`，首次运行就写注册表自启 | **`false`**，不写注册表；设置窗口「开机自动启动」与托盘菜单是同一个开关，勾上/取消立即生效 |
| 首装日程 | 自动写入 3 条示例任务 | **空**：`{"items":[],"lastFired":{}}`；示例改名 `SAMPLE_TASKS`，只有点「一键加回示例任务」才写入 |
| 空日程气泡 | 「今天没有安排」 | **「今天还没有日程～」+「右键我 → 时段任务，加一条吧」**；「接下来」页空时显示「现在还没有日程～」；首次启动主动飘一次（`tipEmptyShown` 只记一次，不再打扰） |

### 顺手修掉一个真实缺陷（提醒被台词顶掉）

日程为空时，「没安排 → 飘一句台词」这条路会把**正在追的提醒**顶掉（点气泡、点菜单都会）。
综合验收第 5 项因此从红转绿：`cycleBubble()` 开头加 `if (S.alert) { showBubble('alert'); return }` —— **提醒永远优先**。

### 测试安全性（重要）

默认值翻成 `false` 之后，验收实例启动时也会走 `setAutoStart()`，于是**每跑一次测试就会删掉使用者自己的自启项**。
新增 `NOTEPAD_PET_NO_AUTOSTART=1`：测试库启动实例时带上它，`setAutoStart()` 直接返回 —— 测试永远不碰真实注册表。
