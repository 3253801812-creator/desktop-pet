# 发布流程（打包 → GitHub）

## 为什么 exe 不进仓库

便携版 exe 是 **108.7 MB**，超过 GitHub 单文件 **100 MB 硬上限**（`git push` 会直接被拒）。
所以约定：**仓库只放源码与文档，exe 一律作为 Release 附件发布**（Release 单个附件上限 2 GB）。
`.gitignore` 里已经忽略 `dist/` 和 `/*.exe`。

## 发一个版本

```powershell
# 1. 改版本号（package.json 的 version）+ 在 CHANGELOG.md 顶部写这次改了什么

# 2. 跑验收（语法 + 20 项综合 + 5 项闹钟跨重启）
npm test

# 3. 打包（产出便携版 + 安装版；国内网络用镜像变量）
$env:ELECTRON_MIRROR="https://registry.npmmirror.com/-/binary/electron/"
$env:ELECTRON_BUILDER_BINARIES_MIRROR="https://npmmirror.com/mirrors/electron-builder-binaries/"
npm run dist

# 4. 打包版冒烟（7 项，直接跑产物）
npm run test:smoke

# 5. 提交源码（不会包含 exe）
git add -A
git commit -m "0.5.15：……"
git tag v0.5.15
git push origin main --tags
```

6. 到 GitHub 的 **Releases → Draft a new release**：Tag 选 `v0.5.15`，
   把 `dist/记事本桌宠-便携版-0.5.15.exe` 和 `dist/记事本桌宠-安装程序-0.5.15.exe` 拖进附件区，
   说明复制 CHANGELOG 里那一节，然后 Publish。

> 装了 [gh](https://cli.github.com/) 的话，第 6 步可以一条命令：
> `gh release create v0.5.15 dist/*.exe -t "0.5.15" -n "见 CHANGELOG"`

## 仓库约定

| 文件 | 作用 |
|---|---|
| `.gitignore` | 排除 `node_modules/`、`dist/`、exe、私有工具、截图中间产物 |
| `.gitattributes` | 源码 LF、`.ps1`/`.bat` 保持 CRLF、二进制不转换 |
| `tests/` | 回归验收（`npm test`），不参与打包 |
| `tools/` | 开发调试脚本，不参与打包 |
| `docs/验收记录.md` | 每个版本的实测结果与排查记录 |

## 两个容易踩的坑

1. **`.ps1` 必须带 UTF-8 BOM**：Windows PowerShell 5.1 没有 BOM 会把中文读成乱码。
   用编辑器改完 `.ps1` 后确认文件头是 `EF BB BF`（本项目测试用 `powershell -File` 跑，属于 5.1）。
2. **打包版只收主代码**：`package.json` 的 `build.files` 限定为 `main.js`、`preload.js`、
   `renderer/**`、`assets/**`（排除 `*.json`）、`package.json`。改完可以用
   `node tools/asar-list.mjs dist/win-unpacked/resources/app.asar` 核对包内清单。
